# 数模侠线上桌游设计

## 已确认的意图

用户于 2026-11-01 确认：大创答辩优先；网页与微信端真实互通；真人组房、AI 补位；文字及语音；AI 阅读聊天、推理、伪装、用技能与投票；保留实体卡面；v2 规则叠加 v4.0 增补，SVD 采用吞噬。优先验证 1–2 真人与 AI 补齐的 8 人局，同时保留 8/10/12/14/16 人配置。无硬截止，希望尽快；AI 与语音试用预算每月上限 100 元。微信账号尚未注册。稳定的预先安排成员演示优先，临时观众扫码加入不是硬性条件。暂不做支付、会员、公开匹配。

## 架构选择及理由

考虑了直接给旧 Python 模拟器接前端、两端各自实现规则、共用可交互游戏服务三条路径。旧引擎同步跑完整晚，发言占位，未实现公式卡，且模拟器会把验出的异常值自动公开给好人，不能直接用于真人局。两端各算规则会导致状态与隐私分歧。因此由开发者选择第三条：独立目录，不改旧资料；纯 JavaScript 规则状态机与协议共用，浏览器与微信客户端只提交动作。旧配置表、实体牌及题库作为内容来源和规则对照。

首个运行入口为 Node.js 24 本地 HTTP 服务，网页同源提供；HTTP JSON 轮询使微信端与网页使用完全相同的房间状态。持久层采用单进程串行动作队列及原子文件快照；部署到多实例时必须换为带版本比较的共享数据库，禁止把进程内 Map 当跨实例持久化。后续托管适配器不得改变规则。Sites 仅在其运行时与共享后端及访问范围匹配时用于整站部署，不能用静态上线冒充联机后端。

## 界面与发言

网页：暖白纸面、原卡牌蓝灰/赭红/墨绿配色，桌面左侧阶段与身份，中部座位桌及动作，右侧对局消息。移动端改为上下排版与底部操作。首页直接创建/加入，不用介绍网站代替游戏。卡牌图鉴用于查规则，游戏中仅显示本人牌及公开信息。微信端交付真实可导入项目及同协议网络层，不能只嵌网页声称原生互通。由于玩法属于游戏，微信普通小程序与小游戏的最终类目须以账号后台核实；提供 Canvas 小游戏适配，避免依赖旧 WXML 骨架的假设。

白天按座位轮流发言，文字直接发送；首版语音是录音消息而非持续多人通话。录音上传到服务端，语音识别完成并经发言者确认后成为公开文字，供真人阅读及 AI 理解。原录音可播放。AI 发言可以合成语音；若服务未配置，明确提示不可用，不虚构识别结果，也不把固定话术标成模型推理。

## 服务端状态及协议

Room 含 code、hostId、revision、phase、round、players、night、votes、publicLog、privateLog、pending、formulaUsed、questions、result、createdAt。玩家含不透明会话凭证；服务端以凭证确定身份，不能相信请求给的 playerId/role/host。

接口：POST /api/rooms 创建；POST /api/rooms/:code/join 加入；GET /api/rooms/:code/state 个人视图；POST /api/rooms/:code/action 动作；POST /api/rooms/:code/tick 推进到期/AI；POST /api/rooms/:code/audio 语音；GET /api/health 非敏感运行状态。请求携带 Authorization: Bearer，会话凭证仅存本机。每个动作含 actionId 及 revision，重复不二次执行，旧版本拒绝并刷新。加入后保留凭证以便断线恢复；开局后不允许陌生人占用已分配身份。房主可以在等待时用 AI 补满并开局，不能读取隐藏身份或控制真人决策。

夜晚统一展示夜晚，不向无关玩家公布具体谁在操作、谁已提交、亡者名单或药品用量。异常值只见队友、夜晚私聊、自己的提名；其他神职只获其允许的信息。AI 用与真人相同的个人视图决策；不接触全状态、别人的私信、题目答案。结算后揭晓全部身份及回放。

## 确定规则与需要统一的边界

- 配置：8=2异常+4神+SVD+1民；10=3+4+1+2；12=4+4+0+4；14=4+4+1+5；16=5+5+1+5；大数仅16人。
- 夜序：异常提名→贝叶斯→回归→置信→死亡计算→SVD→天亮。异常可空刀或选择任意存活者，多数决，平票随机；不能提前公布提名。
- 守护不能自守，可连续守同人；置信药不能自救，救毒各一次，同夜允许两药；守救同时命中时守优先且救药不消耗。毒不受守护影响，SVD 可被毒；方差任何出局均可带人，包括被毒。
- SVD 每夜可在当夜死亡候选中吞噬一人得知阵营，不得知道神职名称。不能吞噬自己；本夜将死的 SVD 不再行动。说明书“吞噬一次”理解为每夜一次，不是全局一次；记录为开发者裁定，允许后续调整。
- 大数首次被公投时翻牌免死，依现引擎保留投票权；只公投触发。猎人及自爆造成出局不翻牌。
- 每人开局一张公式卡，6种各3份的实体牌池随机发放。同一种公式每个白天至多生效一次；用过丢弃，无人可见他人手牌。
- 洛必达在投票前取消当日公投；泰勒私下查一名存活者阵营；柯西指定当日不能投/被投者。
- 拉格朗日不让系统裁判自由文字真假：双方从真实的可验证私人信息条目中各选一条公开，等待对方确认；不存在私有信息时允许公开自身阵营，明确提示将暴露该信息。两边提交后一起公开；拒绝/超时不扣牌。
- 傅里叶在投票锁定后、执行淘汰前的反应窗口使用；唯一最高者免死，按其余玩家中的次高选择。最高本身平票或次高平票进入一次重投；仍平则平安日。反应窗口结束后不能反转已经执行的死亡。最高者被该卡保护至本次公投结束。
- 黎曼指定一位已出局者，在下一轮白天增加一次遗言发言；不恢复技能/投票/普通聊天权，也不再触发答题。
- 公投最多重投一次；每轮投票均可弃票，不能投自己。已淘汰者没有正常发言/投票权。异常白天自爆先完成出局技能与遗言，再跳过余下白天进入夜晚。
- 死亡先进入方差带人链，再按顺序答题遗言，之后检查胜负，确保终局死者也有最后答题机会。答对普通题+1、专业题+2；答错可跳过无现实强制惩罚；答案和解析仅提交/超时后公布。
- 题面以 v4 实体牌 deck.py 为主，50道唯一题，甲乙复制不作为100道不同题。旧 questions.json 与实体题存在内容差异，不能直接宣称同款。等价简答用白名单归一化判分；证明题不声称自动证明，使用受控选择题或人工核对并留痕，不交给任意关键字命中。
- 正义：异常及SVD全灭；异常存活且神边或民边全灭；SVD：异常全灭且正义至多1人。按边是否在开局存在守卫。无预设胜负、无超时静默判某阵营胜。

## AI 及成本

模型供应商通过服务端环境配置，采用可替换的 HTTP 适配。每次只发送公开记录与本人允许的信息；输出限定为合法动作列表、简短发言，不要求公开私有思维链。异常可在公开发言伪装，不得给其他玩家泄露未授权私信。对聊天中的指令注入维持角色和信息边界。

未配置密钥/网络错误/超预算时走明确标记的规则机器人，仍可完整游玩；设置页显示当前实际模式及错误，不能将它冒充用户要求的模型 AI。真正的 A 级 AI 和跨端语音验收需要用户配置服务并实测。

月预算100元是应用内估算限额；输入输出单价由所用服务实际账单填写；未设价格时不承诺精确费用。请求前按最大token/时长预留，成功后结算，失败保留合理费用记录，服务端串行防止同时突破限额。该上限仅覆盖本应用请求，服务器/域名另列，不擅自购买任何服务。

## 验收与外部依赖

自动化：全部配置合法；夜晚死亡与连锁、公投平票、六张公式时序；本人/异常队友视图；AI上下文无越权信息；动作幂等与版本冲突；掉线/重连；答题答案提交前不泄露；预算并发；两个独立会话同房跑到结算，真实投票影响结果。

浏览器：桌面及手机截图检查；实际创建、加入、补AI、开局、点击动作、发言、答题、结算。微信可导入构建、同协议客户端测试不能替代真机扫码验证。真机扫码尚需用户注册账号、获取AppID、上传体验版、成员授权及后端HTTPS合法域名等平台配置，最终以当期官方后台为准；无法代替用户进行身份验证。语音须麦克风权限、可用服务及手机真机验证。必须在交付说明中分别列出已验证与待验证内容。
