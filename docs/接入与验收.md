# 接入与验收

本文帮助首次使用者完成模型、语音与微信的真实接入。当前没有用户的模型密钥、微信AppID或公网主机；不能把适配器代码和协议测试当作真实服务验证完成。

## 一 先准备一个模型服务账号

当前适配示例采用硅基流动的文字、ASR、TTS HTTP接口，便于一个服务端统一配置。它只是可更换的接入选择，没有替你注册或购买任何服务。

1. 打开 [服务商控制台](https://cloud.siliconflow.cn/)，由你本人注册、登录并完成当期后台要求。
2. 在 [API密钥页面](https://cloud.siliconflow.cn/account/ak) 创建项目专用密钥，保存在本机。不要发到聊天、截图或前端代码中。
3. 到控制台模型列表，复制当前可用的文字模型完整ID。名称必须包含提供商前缀，不能只写“Qwen”或“DeepSeek”。模型上下线、能力和价格以你的当前控制台为准；本项目不预先保证某型号永久免费或效果达到真人水平。
4. 将 `.env.example` 复制为 `.env`，填写 `AI_API_KEY`、`AI_MODEL`、输入与输出token单价。输入/输出单价单位是“元/百万token”。只有控制台确认免费时才填0；留空代表不启用。
5. 如果要识别语音，确认账号支持 `FunAudioLLM/SenseVoiceSmall`，并按实际价格填写 `ASR_PER_MINUTE`，单位“元/分钟”。
6. 若要云端语音回应，确认账号支持 `FunAudioLLM/CosyVoice2-0.5B` 及所填音色，并填写 `TTS_PER_THOUSAND_CHARS`，单位“元/千字符”。
7. 重新启动服务。首页顶部与“服务状态”页会显示已配置的能力，但“已配置”仍不等于已验证；下一节需做真实调用。

接口实现依据 [语音识别官方接口](https://docs.siliconflow.cn/docs/api/audio-transcriptions-post)、[语音合成官方说明](https://docs.siliconflow.cn/docs/userguide/capabilities/text-to-speech) 与 [平台对模型名称及接口地址的说明](https://docs.siliconflow.cn/docs/usercases/use-siliconcloud-in-eechat)。文字接口采用 `/chat/completions`，要求可输出JSON；不同供应商的参数兼容性需实际验证后调整。

预算默认每月100元，本应用请求前按最坏用量预留，再按返回用量结算；失败可能已计费，因此保守保留预留。预算跨重启保留在 `.data/budget.json`。不要删除该文件来“恢复额度”。这是应用内估算，实际扣费以服务商账单为准，服务器、域名费用不包含在此项。模型实际能力与费用需要用一场对局测量。

## 二 真实AI和语音测试

1. 创建一个8人房，真人自己入座，机器人补齐。确认顶部显示模型已配置。
2. 在夜晚让模型做一次技能决策，白天让模型针对真人发言回应。查看“服务状态”最近错误；若降级，页面不得继续声称本次用了模型。
3. 确认模型能主动使用自己的公式卡，查验结果不会自动出现在其他人的信息栏。
4. 轮到自己发言时录音，停止后应拿到转写文字，人工检查再发送。AI只会在你发送后读到这段公开文字，不监听未发送的录音。
5. 从另一台客户端播放原录音。点击AI发言的播放按钮，验证合成语音；两名用户同时点同一条发言，只应触发一次服务请求。
6. 结束一局后核对控制台实际账单、应用估算、平均响应时间和降级次数，再决定是否换模型或缩短发言。

录音不是多人持续语音通话：首版采用最长55秒的语音消息，服务端接受最长60秒的16kHz单声道PCM/WAV。浏览器需要麦克风权限与安全连接，微信录音需要对应运行时能力、隐私声明和授权。尚未做真实设备语音验证。

## 三 微信账号及手机扫码

1. 从 [微信公众平台](https://mp.weixin.qq.com/) 进入注册流程。先核实该桌游应使用的游戏类目、可用主体、体验权限与发布要求，避免沿用普通小程序旧骨架后再返工。微信官方开发文档本次访问失败，本文不把第三方文章中的资质要求当成已确认结论。
2. 下载 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，用你本人管理的微信登录。
3. 导入本项目 `wechat/`，这是一个带 `game.js` 和 `game.json` 的原生Canvas小游戏项目。`touristappid` 只是本地占位，不能算手机扫码验收成功。换成账号后台提供的正式AppID。
4. 准备独立可达的HTTPS后端地址，将 `wechat/config.js` 的 `backendUrl` 改为该地址。在微信后台按实际要求配置请求、下载和分享相关域名；录音与隐私声明按后台当期要求补齐。
5. 开发者工具先验证编译和请求。真机不能使用 `127.0.0.1` 访问电脑；普通网页里的localhost也不是公共游戏服务器。
6. 上传体验版，并按后台流程让演示用的微信号具备体验权限，再用手机扫码。由另一名真人在网页端加入相同房间号，实际跑完一局。
7. 只有这一步完成，才在验收记录中勾选“微信真机与网页互通”。评委临时扫码加入是否可用取决于最终账号及发布配置，首版不把它作为硬性条件。

## 四 公网后端部署

现有交付是Node.js单进程服务，需要你提供可用的主机及HTTPS域名。可以在自有服务器上运行，或使用能保留磁盘且只启动一个实例的Node托管服务；应用数据目录应持久保留并备份。

提供了 `Dockerfile`，服务端通过环境变量配置，监听8080端口；把 `/app/.data` 挂载到持久卷。HTTPS由前置代理或托管平台提供。不要把Node调试端口或运行数据目录公开。私有网页托管的登录页面不能冒充微信可访问的后端。本项目没有自动购买服务器、注册域名或公开上传你的桌游资料。

开发时的本地服务不等于公网部署；协议模拟也不等于微信手机运行。部署后需在实际网络检查请求时延、音频上传和密钥保护。

## 五 答辩演示步骤

1. 演示前测试同一房间的网页、微信与模型服务；保留文字方式作为语音故障时可见的后备。
2. 展示原实体卡与线上本人卡面，说明身份只有本人能看。
3. 两名真人加入，AI补齐8人。完成一次夜晚技能，展示角色拥有不同信息。
4. 真人发言，AI按实际模型回应；现场没接模型时必须如实称规则机器人。
5. 使用一次公式卡，完成公投、出局答题和徽章；一局结束后展示全部身份和回放。

本版没有预设胜负或按脚本生成“成功”记录。若答辩时长短于完整一局，可提前运行到合适阶段继续展示，并明确这是同一场已在进行的真实对局。
